## 5.1 监测数据自动生成

### 5.1.1 数据生成器设计

监测数据自动生成服务模拟真实监测站的数据采集过程。服务基于Node.js的node-cron定时任务库实现，每5分钟自动执行一次数据生成。

生成器根据监测站类型生成对应的数据类型。系统定义了8种监测站类型与数据类型的映射关系，例如rainfall站生成rainfall、temperature、humidity三种数据，slope站生成slope_displacement、rainfall、soil_moisture三种数据。这种设计符合真实场景：并非每个监测站都具备所有传感器，不同站点监测不同的指标。

核心代码实现如代码清单5-1所示。

### 5.1.2 数据生成算法

数据生成遵循真实物理规律，考虑时间因素、地理因素和随机扰动。以降雨量生成为例：

```typescript
generateRealisticRainfall(): number {
  const hour = new Date().getHours();
  const isNight = hour < 6 || hour >= 22;
  
  // 大部分时间不下雨
  if (Math.random() < 0.85) {
    return 0;
  }
  
  // 夜间降雨量通常较小
  const maxRainfall = isNight ? 5 : 10;
  return Math.random() * maxRainfall;
}
```

坡面位移数据生成模拟正常微小位移和异常大位移两种情况：

```typescript
generateSlopeDisplacement(): number {
  // 5%概率出现明显位移（危险信号）
  if (Math.random() < 0.05) {
    return 1 + Math.random() * 4;  // 1-5mm
  }
  return Math.random() * 0.5;  // 正常微小位移
}
```

生成的数据除基本的value值外，还填充raw_data和processed_data两个JSONB字段，分别记录传感器原始信息和数据处理信息，为后续的质量控制和异常检测提供依据。

## 5.2 机器学习风险评估实现

### 5.2.1 随机森林算法原理

随机森林（Random Forest）是一种集成学习算法，由多个决策树组成。每棵树在训练时使用随机抽样的数据子集和随机选择的特征子集，预测时综合所有树的投票结果，这种机制降低了过拟合风险，提高了泛化能力[2,3]。

图5-1展示了随机森林的预测流程。

**图5-1 随机森林预测流程**

```
输入特征向量
[rainfall, groundwater, slope, soil_moisture, 
 seismic, population, temperature]
         │
         ├──────┬──────┬──────┬─────┬──────┐
         │      │      │      │     │      │
         ▼      ▼      ▼      ▼     ▼      ▼
      决策树1  决策树2 决策树3 ... 决策树99 决策树100
         │      │      │      │     │      │
      等级3   等级3   等级4  等级3 等级3  等级3
         │      │      │      │     │      │
         └──────┴──────┴──────┴─────┴──────┘
                       │
                    投票统计
                       │
                    等级3(70票)
                    等级4(30票)
                       │
                  输出：等级3
                  置信度：0.70
```

随机森林的置信度来自预测概率分布。如果100棵树中有70棵预测为3级，30棵预测为4级，则输出3级，基础置信度为0.70。

### 5.2.2 模型训练实现

聚合算法的Python实现：

```python
def aggregate_monitoring_to_features(monitoring_data):
    features = {}
    data_by_type = {}
    
    for record in monitoring_data:
        data_type = record['data_type']
        value = float(record['value'])
        if data_type not in data_by_type:
            data_by_type[data_type] = []
        data_by_type[data_type].append(value)
    
    if 'rainfall' in data_by_type:
        features['rainfall'] = min(max(data_by_type['rainfall']), 10)
    
    if 'groundwater_level' in data_by_type:
        avg_level = sum(data_by_type['groundwater_level']) / 
                    len(data_by_type['groundwater_level'])
        features['groundwater'] = max(0, 10 - avg_level / 2)
    
    # 其他数据类型类似处理...
    
    return features
```

### 5.2.4 置信度计算方法

```python
if valid_features_count >= 6:

elif valid_features_count >= 4:
    adjusted_confidence = base_confidence * 1.25  # 加成25%
elif valid_features_count >= 2:
    adjusted_confidence = base_confidence * 1.10  # 加成10%
else:
    adjusted_confidence = base_confidence * 0.95  # 小幅降低

# 限制在合理范围
adjusted_confidence = min(0.95, max(0.65, adjusted_confidence))
```

测试表明，当监测数据齐全时（8种数据类型），置信度可达85%-92%；数据不全时（2-3种），置信度为65%-75%。

## 5.2 A*路径规划算法实现

### 5.2.1 路网图构建

路径规划基于OpenStreetMap导入的35,513条道路数据。首先需要将道路线段转换为图结构。

**（1）节点提取**

遍历每条道路的LineString几何，提取起点和终点的坐标作为节点。相近的节点（距离<11米）进行合并，避免冗余节点。最终得到5,984个节点。

节点数据结构：

```typescript
interface GraphNode {
  id: string;              // 节点ID
  location: Point;         // 位置（经纬度）
  connections: Map<string, number>;  // 连接关系（邻节点ID:距离）
}
```

**（2）边构建**

两个节点如果由道路连接，则建立边，边的权重为道路长度。遍历35,513条道路，建立了13,222条有向边（双向道路算两条边）。

图结构构建完成后，保存在内存中，供A*算法使用。

### 5.2.2 A*算法实现

A*算法是一种启发式搜索算法，通过评估函数f(n) = g(n) + h(n)选择最优路径[8]。其中g(n)是从起点到当前节点的实际代价，h(n)是从当前节点到终点的估计代价（启发函数）。

图5-3展示了A*算法的执行流程。

**图5-3 A*算法流程图**

```
        开始
         │
         ▼
    初始化openSet
    起点加入openSet
         │
         ▼
    ┌─> openSet为空？─Yes─> 失败，无路径
    │    │No
    │    ▼
    │  取出f值最小的节点current
    │    │
    │    ▼
    │  current是终点？─Yes─> 成功，回溯路径
    │    │No                      │
    │    ▼                        ▼
    │  将current加入closedSet   构造路径点序列
    │    │                        │
    │    ▼                        ▼
    │  遍历current的邻居节点     返回路径
    │    │
    │    ▼
    │  邻居在closedSet？─Yes─> 跳过
    │    │No
    │    ▼
    │  计算g = current.g + 距离
    │  计算h = 直线距离到终点
    │  计算f = g + h
    │    │
    │    ▼
    │  邻居在openSet？─No─> 加入openSet
    │    │Yes                    │
    │    ▼                       │
    │  新路径更优？─Yes─> 更新节点
    │    │No         │          │
    │    ▼           │          │
    └──跳过◄─────────┴──────────┘
```

启发函数h(n)使用Haversine公式计算球面距离，考虑地球曲率：

```typescript
private calculateHeuristic(from: Point, to: Point): number {
  const R = 6371000;  // 地球半径（米）
  const lat1 = from.coordinates[1] * Math.PI / 180;
  const lat2 = to.coordinates[1] * Math.PI / 180;
  const dLat = (to.coordinates[1] - from.coordinates[1]) * Math.PI / 180;
  const dLon = (to.coordinates[0] - from.coordinates[0]) * Math.PI / 180;
  
  const a = Math.sin(dLat/2) * Math.sin(dLat/2) +
            Math.cos(lat1) * Math.cos(lat2) *
            Math.sin(dLon/2) * Math.sin(dLon/2);
  const c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1-a));
  
  return R * c;  // 返回米
}
```

### 5.2.3 风险避让策略

在标准A*算法基础上，系统引入了风险因素。计算路径时检查路径是否穿过风险区域，使用PostGIS的ST_Intersects函数：

```sql
SELECT rz.id, rz.base_risk_level
FROM risk_zones rz
WHERE ST_Intersects(
  rz.geometry,
  ST_MakeLine(ARRAY[起点, 终点])
);
```

如果路径穿过风险区域，根据风险等级调整代价：

```typescript
let riskFactor = 1.0;
if (riskLevel >= 4) {
  riskFactor = 1.5;  // 高风险区域代价增加50%
} else if (riskLevel === 3) {
  riskFactor = 1.2;  // 中风险区域代价增加20%
}
adjustedCost = actualDistance * riskFactor;
```

这样，算法倾向于选择绕开高风险区的路径，即使距离稍远，也会选择更安全的路线。

### 5.2.4 性能优化

A*算法的性能关键在于openSet的数据结构。本系统使用最小堆（Priority Queue）存储openSet，保证每次取出f值最小的节点只需O(log n)时间复杂度。

测试案例（海淀香山到最近避难所）：
- 路径长度：4.13公里
- 途经节点：64个
- 计算时间：8秒
- 搜索节点数：约1,200个（占总节点的20%）

相比Dijkstra算法的全图搜索（需30秒），A*算法提升了近4倍效率。
