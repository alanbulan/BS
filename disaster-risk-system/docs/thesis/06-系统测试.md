# 第6章 系统测试

## 6.1 测试环境

### 6.1.1 硬件环境

测试在以下硬件配置的计算机上进行：处理器Intel Core i7-12700H，主频2.3GHz，12核心；内存32GB DDR4；硬盘512GB SSD；操作系统Windows 10专业版64位。

### 6.1.2 软件环境

软件环境包括：PostgreSQL 15.0数据库，PostGIS 3.3扩展；Node.js 20.11运行环境；Python 3.10.11解释器；Chrome 120.0浏览器；Android 13模拟器（用于移动端测试）。

开发工具使用Visual Studio Code 1.85，数据库管理使用pgAdmin 4.38，接口测试使用Postman 10.19。

### 6.3.3 数据库性能测试

测试PostGIS空间查询的性能表现。

**查询1：点在多边形内判断**（模拟用户位置在风险区域内判断）

```sql
SELECT * FROM risk_zones 
WHERE ST_Contains(geometry, ST_MakePoint(116.4, 39.9));
```

测试结果：
- 无GIST索引：平均25ms
- 有GIST索引：平均5ms
- 性能提升：5倍

**查询2：查找附近避难所**（10公里范围）

```sql
SELECT * FROM shelters 
WHERE ST_DWithin(location::geography, point::geography, 10000);
```

测试结果：
- 无索引：平均12ms
- 有索引：平均3ms  
- 性能提升：4倍

**查询3：监测数据关联查询**（查询某区域24小时数据）

```sql
SELECT md.* FROM monitoring_data md
INNER JOIN monitoring_stations ms ON md.station_id = ms.station_id
WHERE ms.zone_id = 9 
  AND md.timestamp >= NOW() - INTERVAL '24 hours'
LIMIT 500;
```

测试结果：
- 无复合索引：平均320ms
- 有(station_id, timestamp)复合索引：平均45ms
- 性能提升：7倍

索引优化显著提升了查询性能，空间索引和复合索引是性能保障的关键。

## 6.4 准确性测试

### 6.4.1 风险评估准确性

为验证机器学习模型的预测准确性，选取历史评估记录进行对比。

测试方法：对已有专家评估结果的10个风险区域，使用ML模型重新评估，对比预测等级与专家判断等级的一致性。

测试结果：10个区域中，7个完全一致，2个相差1级，1个相差2级，一致性达到70%，基本一致率（相差≤1级）达到90%。考虑到专家评估本身也存在一定主观性，该准确率属于可接受范围。

典型案例对比：
- 门头沟妙峰山：专家评估4级，ML预测4级，完全一致
- 海淀香山：专家评估3级，ML预测3级，完全一致
- 延庆八达岭：专家评估2级，ML预测3级，相差1级

误差分析发现，ML模型倾向于在数据不足时给出保守估计，这在安全角度是可以接受的。

### 6.4.2 路径规划准确性

路径规划的准确性体现在两个方面：路径可达性和距离准确性。

测试10组起点终点，A*算法均成功找到路径，可达性100%。对比计算的路径长度与实际道路长度（从OpenStreetMap查询），误差在5%以内。例如香山到避难所，计算距离4.13km，实际道路距离约4.3km，误差4%。

路径的合理性通过人工检查验证。随机抽查5条路径，在Google Maps上对比，均为合理路线，无绕行或死路。
